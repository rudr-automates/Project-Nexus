# Development Rules

These rules apply to every future contribution to Project Nexus.

---

# Repository

- Keep folders organized.
- Avoid unnecessary restructuring.
- Document architectural changes.
- Prefer readability over cleverness.

---

# Infrastructure

- Docker-first deployment.
- Infrastructure must remain reproducible.
- No manual production fixes.
- Prefer configuration over customization.

---

# Code

- Write maintainable code.
- Remove dead code.
- Keep modules focused.
- Avoid duplication.
- Follow existing architecture.

---

# Documentation

Documentation is part of the product.

Every major change should update the relevant documentation.

---

# AI

AI enhances engineering.

AI does not replace engineering.

Automation should continue functioning without AI whenever practical.

---

# Pull Requests / Commits

Each milestone should produce:

- Working platform
- Updated documentation
- Clean commit history

---

# General Principle

Whenever multiple implementations exist:

Choose the one that is:

- simpler
- more maintainable
- easier to debug
- easier to extend
